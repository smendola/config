# ~/.dsh

DeepSeek Harness home (`$DSH_HOME`). The active profile is `web`
(`DSH_PROFILE=web`). The running harness is a published npx install, so there
is no `packages/` source tree here to patch — customize through bundles.

This directory is the git repository that reproduces the whole setup on another
machine. Both bundles are fetched from GitHub; nothing lives under `plugins/`.

## Replicating this setup

**Model.** `~/.dsh` is the repo root, not `profiles/web/`, because the profile
`package.json` references bundles by name; tracking only the profile would
commit a manifest whose targets live elsewhere. Both bundles
(`dsh-reasoning-pruner`, `dsh-opencode-mcp-parity`) are installed from GitHub
by pinned commit sha. `plugins/` is empty and not tracked.

**What to track** — seven files under `~/.dsh` (plus the home-root
`~/.gitignore`):

| Path | Why it must be tracked |
|---|---|
| `README.md` | This document; the only written record of intent and drift. |
| `.gitignore` | See the block below. |
| `.env.example` | Names the four env vars the profile references; values are never committed. |
| `profiles/web/cordis.patch.yml` | The hand-edited profile layer: theme, `fontSize`, `busyEnter`, both LLM providers (`cuda-linux-llama`, `cuda-linux-strata`) with model lists, default model, agent preset defaults. |
| `profiles/web/package.json` | `dsh.profile.bundles` order plus the two bundle specs (GitHub pins). |
| `profiles/web/pnpm-workspace.yaml` | `nodeLinker: hoisted`, `autoInstallPeers: false`. |
| `profiles/web/pnpm-lock.yaml` | Locks both GitHub pins to commit shas. |

The bundle sources live in their own repos, not here:

- [smendola/dsh-reasoning-pruner](https://github.com/smendola/dsh-reasoning-pruner)
  (local checkout `~/repos/dsh-reasoning-pruner`)
- [smendola/dsh-opencode-mcp-parity](https://github.com/smendola/dsh-opencode-mcp-parity)
  (local checkout `~/repos/opencode-mcp-parity`)

Only their pins are tracked, in `package.json` and `pnpm-lock.yaml`.

**What not to track.** None of it is configuration; all of it either contains
secrets or is regenerated by booting the profile.

| Path | Why |
|---|---|
| `profiles/node_modules/` | A hoisted link farm created at first boot. `@deepseek-ai/dsh` is a symlink into the npx cache (`~/.npm/_npx/<hash>/node_modules/...`), so the paths are machine- and version-specific. |
| `profiles/web/node_modules/` | pnpm output; refetches from the manifest and lockfile. |
| `profiles/web/.plugin-manager/` | Per-install operation logs. |
| `profiles/web/cordis.yml` | Generated file; its own header says not to edit it. |
| `profiles/web/cordis.patch.yml.bak` | Stale copy from 2026-10-01 (old single provider `cuda-linux`, old default model, `selectedDefault: cordis`). Delete or ignore it. |
| `plugins/` | Empty; a leftover from when bundles were local `link:`s. |
| `sessions/` | Transcripts, one directory per workspace cwd. |
| `storages/` | Session projection cache plus `workspace.json` (workspace UUIDs, pinned/archived session ids). |
| `logs/` | Startup logs plus `reasoning-pruner.log`. |
| `cache/`, `attachments/`, `llm-deepseek/` | Scratch and blob cache; safe to clear. |
| `.credentials.yaml` | Secrets — holds refs for the CUDA keys plus the browser session secret. |
| `.anonymous-user-id` | Per-install identity. |
| `settings.yaml.imported` | Legacy pre-Cordis import; not read. |

**Portability.** There are no `/home/sal` paths left in any tracked file:

- Both bundle specs are GitHub pins (portable by construction).
- `dsh-opencode-mcp-parity`'s generated patch rewrites every `$HOME` path to
  `!!js '`${process.env.HOME}/…`'`.
- `dsh-reasoning-pruner` has no paths at all.

Secrets and the harness version still live outside the repo. The tracked files
reference `CUDA_LINUX_API_KEY`, `CUDA_LINUX_STRATA_API_KEY`,
`CONTEXT7_API_KEY` and `SENDGRID_API_KEY` by name only; the values are in
`.credentials.yaml` and the environment (see `.env.example`). Pin the harness
here: `@deepseek-ai/dsh@0.2.1-rc.2`.

**Restore on a new machine.**

```bash
npx @deepseek-ai/dsh@0.2.1-rc.2 web       # boot once: creates ~/.dsh and the shipped web profile
git clone <config-repo> ~/dsh-config
rsync -a --exclude .git ~/dsh-config/ ~/.dsh/
cd ~/.dsh && dsh plugin --profile web install   # fetches both bundles from GitHub
dsh --profile web --dump-config                 # confirm the composed tree
```

Then populate the four environment variables, or re-add them through the UI so
`.credentials.yaml` is rebuilt. Restore needs network access to GitHub.

## Installed bundles

Both from GitHub, pinned by commit sha in `profiles/web/package.json`:

- `dsh-reasoning-pruner` — Host plugin; strips reasoning blocks from completed
  turns before the model request is sent.
- `dsh-opencode-mcp-parity` — generated configuration-only bundle mirroring the
  MCP servers from `~/.config/opencode/opencode.jsonc`. Documented below.

## `dsh-opencode-mcp-parity`

**What it is.** A configuration-only bundle whose `cordis.patch.yml` is
**generated**, not hand-edited. The generator lives in
[smendola/dsh-opencode-mcp-parity](https://github.com/smendola/dsh-opencode-mcp-parity)
(local checkout `~/repos/opencode-mcp-parity`):

```
opencode.jsonc ──► generate.mjs ──► cordis.patch.yml ──► DSH bundle
                     ▲
                     └─ sync.config.json   (DSH-only policy)
```

`generate.mjs` reads the `mcp` block of `~/.config/opencode/opencode.jsonc`,
applies the DSH-side policy in `sync.config.json`, and writes the patch.
Deterministic output (no timestamps), so it diffs cleanly. `cordis.patch.yml`
is committed, so the repo also installs directly as a bundle.

**To re-sync** after opencode changes:

```bash
cd ~/repos/opencode-mcp-parity
node generate.mjs                 # rewrites cordis.patch.yml from the live opencode config
git diff                          # review
git commit -am "re-sync MCP rows" && git push
```

Then bump the pin in `profiles/web/package.json` + `pnpm-lock.yaml`
(`pnpm install` after editing), and restart the harness.

**DSH-side policy** lives in `sync.config.json`, not in the generated file:
`disabled` (force-off with a reason), `failOnStartupError`, `extra` (config keys
opencode doesn't express, e.g. `solidcraft.cwd`), `exclude`, `comments`.

**Field mapping** (in `lib.mjs`):

| opencode | DSH (`dsh-mcp-client`) |
|---|---|
| `type: "remote"` + `url` | `transport: streamable-http` + `url` |
| `type: "local"` + `command: [...]` | `transport: stdio`, `command` + `args` |
| `command: ["/usr/bin/env", "-C", DIR, CMD, …]` | `command` + `cwd: DIR` |
| `environment` | `env` |
| `headers` | `headers` |
| `{env:NAME}` | `!!js (process.env.NAME \|\| "")` |
| `"… {env:NAME} …"` | `!!js` template literal |
| `enabled: false` | `disabled: true` |
| `oauth: {...}` | not supported — row forced `disabled` |
| leading `$HOME` path | `!!js '`${process.env.HOME}/…`'` (portable) |

**The eight rows** (as generated on 2026-10-28):

| Server | Transport | Effective state | Notes |
|---|---|---|---|
| `context7` | streamable-http | **enabled** | `Authorization: Bearer $CONTEXT7_API_KEY`. `failOnStartupError: true`. |
| `chrome-devtools` | stdio (`npx -y chrome-devtools-mcp@1.11.0 …`) | **enabled** | Was absent from the old hand-authored bundle; now mirrored faithfully. |
| `solidcraft` | stdio | **enabled** | `solidcraft-cli mcp --allow-any-path`, `cwd` set by `sync.config.json` `extra`. |
| `freecad` | stdio | disabled | opencode has `enabled: false`; the generator sets `disabled: true` directly. |
| `asana` | streamable-http | disabled | Forced off: opencode uses OAuth, which `dsh-mcp-client` does not implement. |
| `sentry` | streamable-http | disabled | Forced off in `sync.config.json`. |
| `postman` | streamable-http | disabled | Forced off in `sync.config.json`. |
| `sendgrid` | stdio (`npx -y sendgrid-mcp`) | disabled | Forced off in `sync.config.json`. |

**Scope.** MCP servers only. opencode's `provider`/`models`, `compaction`,
`keybinds`, `formatter`/`lsp` and `plugin` blocks are **not** mirrored here. The
llama.cpp and Strata providers and their model lists live in
`profiles/web/cordis.patch.yml` and drift independently — check them separately
(see `dsh-opencode-sync` for a provider-sync tool).

## Editing configuration

- **Bundle pins:** both bundles are GitHub pins in `profiles/web/package.json`.
  Bump a pin by editing the sha and re-running `pnpm install` (updates the
  lockfile), then restart the harness. New bundles either get their own repo
  and pin, or — for local-only code — a `link:` into a directory you keep under
  `plugins/`.
- **Profile settings:** edit `profiles/web/cordis.patch.yml`. It is applied after
  every bundle layer. `dsh --profile web --dump-config` prints the composed
  result for checking.
