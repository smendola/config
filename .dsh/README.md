# ~/.dsh

DeepSeek Harness home (`$DSH_HOME`). The active profile is `web`
(`DSH_PROFILE=web`). The running harness is a published npx install, so there
is no `packages/` source tree here to patch — customize through bundles.

This directory is also meant to be the git repository that reproduces the whole
setup on another machine. Start there.

## Replicating this setup

**Model.** `~/.dsh` is the repo root, not `profiles/web/`, because the profile
`package.json` links bundles that live in `plugins/`; tracking only the profile
would commit dangling links. As of 2026-10-28 `~/.dsh` is **not yet** a git
repository (`git init` here, then commit the files below).

**What to track** — eleven files, roughly 10 KB total:

| Path | Why it must be tracked |
|---|---|
| `README.md` | This document; the only written record of intent and drift. |
| `.gitignore` | New; see the block below. |
| `profiles/web/cordis.patch.yml` | The hand-edited profile layer. Holds theme, `fontSize`, `busyEnter`, both LLM providers (`cuda-linux-llama`, `cuda-linux-strata`) with their model lists, the default model, the agent preset defaults, and the `mcp-freecad` disable. This file is most of the setup. |
| `profiles/web/package.json` | `dsh.profile.bundles` order plus the two plugin links. |
| `profiles/web/pnpm-workspace.yaml` | `nodeLinker: hoisted`, `autoInstallPeers: false`. |
| `profiles/web/pnpm-lock.yaml` | Only meaningful once the links are relative (see blocker 1). Then it locks the link paths for portable reinstall. |
| `plugins/dsh-reasoning-pruner/package.json` | Bundle manifest (`dsh.bundle.patch`). |
| `plugins/dsh-reasoning-pruner/index.js` | The plugin code; exists nowhere else. |
| `plugins/dsh-reasoning-pruner/cordis.patch.yml` | Inserts the `reasoning-pruner` row. |
| `plugins/opencode-mcp-parity/package.json` | Configuration-only bundle manifest. |
| `plugins/opencode-mcp-parity/cordis.patch.yml` | The seven MCP rows; the whole bundle. |

**What not to track.** None of it is configuration; all of it either contains

| Path | Why |

**Three blockers to portable replication.**

1. **`profiles/web/package.json` hardcodes `/home/sal`.** The dependencies are
   `link:/home/sal/.dsh/plugins/...`, so a different `$HOME` breaks the profile.
   A relative specifier works: tested 2026-10-28 with pnpm 11.2.2, the link
   resolves and pnpm records it relative in `pnpm-lock.yaml`.

   ```json
   "dependencies": {
     "@local/opencode-mcp-parity": "link:../../plugins/opencode-mcp-parity",
     "dsh-reasoning-pruner":       "link:../../plugins/dsh-reasoning-pruner"
   }
   ```

   Caveat: `plugin_manager install_bundle` rewrites these links back to absolute
   paths, so after installing a new bundle, re-apply the relative form.

2. **`plugins/opencode-mcp-parity/cordis.patch.yml` hardcodes four absolute
   paths:** `/home/sal/miniconda3/bin/freecad-mcp`,
   `/home/sal/.local/bin/solidcraft-cli`, and `cwd: /home/sal/Documents/SolidCraft`
   (twice, for freecad and solidcraft). The file already proves `!!js` templates
   work — the Context7 header uses one — so make them home-relative:

   ```yaml
   command: !!js '`${process.env.HOME}/.local/bin/solidcraft-cli`'
   cwd: !!js '`${process.env.HOME}/Documents/SolidCraft`'
   ```

3. **Secrets and the harness version live outside the repo.** The tracked files
   reference `CUDA_LINUX_API_KEY`, `CUDA_LINUX_STRATA_API_KEY`,
   `CONTEXT7_API_KEY` and `SENDGRID_API_KEY` by name only; the values are in
   `.credentials.yaml` (a `refs:` map for the two CUDA keys, plus a
   `client-connection/browser-session` record) and in the environment. Keep a
   `.env.example` naming the four variables, and pin the harness in this file:
   `@deepseek-ai/dsh@0.2.1-rc.2`.

**Restore on a new machine.**

```bash
npx @deepseek-ai/dsh@0.2.1-rc.2 web     # boot once: creates ~/.dsh and the shipped web profile
git clone <repo> ~/dsh-config
rsync -a --exclude .git ~/dsh-config/ ~/.dsh/
cd ~/.dsh && dsh plugin --profile web install   # relink the bundles into node_modules
dsh --profile web --dump-config                 # confirm the composed tree
```

Then populate the four environment variables, or re-add them through the UI so
`.credentials.yaml` is rebuilt.

## Installed bundles

- `plugins/dsh-reasoning-pruner` — Host plugin; strips reasoning blocks from
  completed turns before the model request is sent.
- `plugins/opencode-mcp-parity` — configuration-only bundle mirroring the MCP
  servers from `~/.config/opencode/opencode.jsonc`. Documented in detail below.

## `opencode-mcp-parity` in detail

**What it is.** A configuration-only bundle: `package.json` declares
`dsh.bundle.patch: ./cordis.patch.yml` and ships no JavaScript at all. The patch
inserts seven `@deepseek-ai/dsh-mcp-client` rows. Nothing compiles, so the whole
edit cycle is "change the YAML, reinstall or restart".

**What it does.** It gives the Harness the same MCP servers opencode has, so one
list of servers serves both tools instead of two drifting lists. Each row starts
a server (stdio) or connects to one (Streamable HTTP) and registers its tools as
`mcp__<serverName>__<tool>`. `~/.config/opencode/opencode.jsonc` is the source of
truth; this bundle is the DSH translation of its `mcp` block.

**Field mapping** used to translate a row:

| opencode | DSH (`dsh-mcp-client`) |
|---|---|
| `type: "remote"` + `url` | `transport: streamable-http` + `url` |
| `type: "local"` + `command: [...]` | `transport: stdio`, `command` + `args` |
| `environment` | `env` |
| `headers` | `headers` |
| `enabled: false` | `disabled: true` on the Loader row |
| — (no equivalent) | `failOnStartupError` — abort activation if the first connect fails |

**The seven rows.**

| Server | Transport | Effective state | Notes |
|---|---|---|---|
| `context7` | streamable-http | **enabled** | Sends `Authorization: Bearer $CONTEXT7_API_KEY`. `failOnStartupError: true` rejects that row's activation if the first connect fails, though the boot policy still lets the harness start without it. |
| `solidcraft` | stdio | **enabled** | `solidcraft-cli mcp --allow-any-path`, cwd `~/Documents/SolidCraft`. Matches opencode's entry exactly (re-synced 2026-10-28). Local, no credentials. |
| `freecad` | stdio | disabled | Inserted enabled by the bundle, then overridden with `disabled: true` by the profile patch — which is why it reads `inactive`. Needs FreeCAD running on its XML-RPC port. Command is the absolute `~/miniconda3/bin/freecad-mcp`; see portability blocker 2. |
| `asana` | streamable-http | disabled | Placeholder. opencode uses OAuth (clientId/secret/redirectUri); `dsh-mcp-client` implements no OAuth, so this row cannot reach parity as configured. |
| `sentry` | streamable-http | disabled | Placeholder. |
| `postman` | streamable-http | disabled | Placeholder. |
| `sendgrid` | stdio (`npx -y sendgrid-mcp`) | disabled | Placeholder, with `SENDGRID_API_KEY`, `READ_ONLY=false`, `REQUEST_TIMEOUT=60000`. |

**Known drift.** Re-synced 2026-10-28: the `solidcraft` row now matches
opencode (both use `--allow-any-path`). The remaining differences are deliberate
or unimplementable:

- opencode now has `asana`, `sentry`, `postman` and `sendgrid` **enabled**; DSH
  still has all four disabled. Enabling them is a one-word edit per row — except
  `asana`, which needs OAuth the client does not implement.
- `solidcraft` was previously `--allow-path ~/Documents/FreeCAD
  ~/Documents/SolidCraft`. The CLI takes one DIR per `--allow-path`, so the
  second path was silently dropped and **only** `~/Documents/FreeCAD` was
  reachable. `--allow-any-path` lifts the limit, matching opencode.
- `freecad` agrees in effect (disabled in both) but through different
  mechanisms: `enabled: false` in opencode, `disabled: true` in the profile patch.
- opencode invokes freecad as `env -C /tmp/opencode …`; the DSH row gets the same
  result from `command` + `cwd: /tmp/opencode`. Equivalent, not a defect.
- opencode's config is **not** in this repository, so the two lists can drift
  again silently. If parity matters, track `~/.config/opencode/opencode.jsonc`
  (or at least its `mcp` block) somewhere versioned.

**Scope.** MCP servers only. opencode's `provider`/`models`, `compaction`,
`keybinds`, `formatter`/`lsp` and `plugin` blocks are **not** mirrored here. The
llama.cpp and Strata providers and their model lists live in
`profiles/web/cordis.patch.yml`, where they have drifted from opencode's
`llama-server` model list independently — check them separately. opencode's
backup shows it once loaded `@ghilteras/opencode-reasoning-pruner`; the DSH
equivalent is the separate `dsh-reasoning-pruner` plugin, not this bundle.

**Re-syncing.** Read the `mcp` block of `~/.config/opencode/opencode.jsonc`,
translate each row with the field mapping above, update the tables, then
reinstall the bundle. Verify by querying `Config.listConfigs` filtered to
`@deepseek-ai/dsh-mcp-client`: active entries report `status: schema`, disabled
ones `inactive`. Reinstalling re-applies the rows in the running harness, but a
row that was already active may keep its existing connection — confirm the
server actually answers rather than trusting the row's presence.

## Editing configuration

- **Bundle:** install with the `plugin_manager` tool (`install_bundle`, absolute
  package directory). It rewrites the profile link and runs pnpm. Don't create
  packages inside the profile. The one exception to "don't hand-edit
  `profiles/web/package.json`" is rewriting the two link specifiers to the
  relative form after an install — do that every time, or the profile stops
  being portable.
- **Profile settings:** edit `profiles/web/cordis.patch.yml`. It is applied after
  every bundle layer (theme, fontSize, busyEnter, LLM providers and models,
  default model, MCP enable/disable). `dsh --profile web --dump-config` prints the
  composed result for checking.
- **New plugin code:** author a bundle (`package.json` with
  `dsh.bundle.patch` + `cordis.patch.yml`) in a workspace directory, then install it.

Keep bundle packages under `plugins/`. A profile entry that links into a scratch
folder breaks the whole profile when that folder moves or is deleted.

## Notes

- **Version:** the running harness is `@deepseek-ai/dsh@0.2.1-rc.2`, installed
  through npx into `~/.npm/_npx/1e7f6d9597241db0/`. Profiles reference that
  absolute path through `profiles/node_modules`, which is one more reason the
  directory is machine-local. Re-run with the same version tag after restoring.
- `reasoning-pruner` currently runs with `debug: true` (the bundle's own default
  is `false`), so `logs/reasoning-pruner.log` keeps growing — it was 2.9 MB on
  2026-10-28. Turn it off in `cordis.patch.yml` once its behavior is settled, and
  settle it before replicating.
- `cordis.patch.yml.bak` (2026-10-01) predates the current provider split
  (`cuda-linux` → `cuda-linux-llama` + `cuda-linux-strata`) and the preset change
  (`selectedDefault: cordis` → `standard`). It is a trap for a future reader;
  delete it rather than committing it.
- A leftover scratch workspace (`envtest/`, `nvmtest/`, `cd_side_effects_test.sh`)
  used to hold the MCP bundle. Nothing in the profile references it any more; it is
  only scratch and can be archived or deleted.
